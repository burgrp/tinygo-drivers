## 1. Chip Modes

| Mode value | Name | Notes |
|------------|------|-------|
| 0 | XN297L (PN297L) | Proprietary 2.4 GHz — Normal and Enhanced sub-modes |
| 1 | FS01 | Proprietary frequency-shift; not covered here |
| 2 | FS32 | Proprietary; not covered here |
| 3 | BLE Beacon | BLE advertising packets; includes LongRange (Coded PHY S2/S8) sub-mode |

All examples use the **32 MHz crystal** and **I2C interface** unless otherwise noted.
See [§10](#10-16-mhz-vs-32-mhz-crystal) for what changes on 16 MHz.

---

## 2. I2C Protocol

- 7-bit device address: **0x71** → wire byte = `0xE2` (write) / `0xE3` (read)
- Register access byte: `reg << 1` for write, `(reg << 1) | 1` for read
- Maximum clock: 2 MHz
- CS pin must be pulled high or left floating when using I2C

```
Write: START | 0xE2 | ACK | (reg<<1)   | ACK | data… | STOP
Read:  START | 0xE2 | ACK | (reg<<1)|1 | ACK | RESTART | 0xE3 | ACK | data… | NACK | STOP
```

If SDA is stuck low at startup, send 10× (8 SCK pulses + STOP) to free the bus before the first register write.

---

## 3. Register Pages

The chip exposes a 7-bit address space (0x00–0x7F) behind two independent register banks:

| Page | Select value | Contents |
|------|-------------|----------|
| Page 0 | `PAGE_CFG` = 0x00 | User/protocol registers — normal operation |
| Page 1 | `PAGE_CFG` = 0x01 | RF analog tuning and calibration — SDK use only |

Two registers are **shared** and accessible from either page without switching:
- `PAGE_CFG` at 0x00
- `STATE_CFG` at 0x02

Always restore `PAGE_CFG` = 0x00 after any Page 1 access.

## 4. Power-On Initialization Procedure

All four chip modes follow the same six-step structure. Only the register values in Steps 4 and 5 differ between modes and crystal frequencies.

### Step 1 — Interface Initialization

```c
WriteReg(0x00, 0x00);   // PAGE_CFG: ensure Page 0
i2c_reset();             // send 10× (8 clocks + STOP) to clear stuck SDA
```

### Step 2 — Enter STB3

STB3 (operating standby, crystal running) is required before registers can be configured and before calibration. The sequence first enters STB3 with the 3V module disabled, then enables it, then asserts and releases soft reset to clear all user registers to defaults.

```c
WriteReg(0x02, 0x04);   // STATE_CFG: exit deep sleep (EN_LS_3V=0, OPERATE_MODE=STB3)
DelayMs(1);
WriteReg(0x02, 0x74);   // STATE_CFG: STB3 + EN_LS_3V=1 (enable 3V analog supply)
DelayMs(1);
WriteReg(0x03, 0x00);   // SYS_CFG: assert SOFT_RSTL (active-low logic reset)
DelayMs(1);
WriteReg(0x03, 0x02);   // SYS_CFG: release SOFT_RSTL — all Page 0 regs back to default
```

`STATE_CFG` key values:

| Value | State |
|-------|-------|
| 0x04 | Deep sleep exit (EN_LS_3V=0) — first entry only |
| 0x74 | STB3, EN_LS_3V=1 — normal idle after init |
| 0x75 | TX mode |
| 0x76 | RX mode |
| 0x21 | Enter sleep |
| 0x22 | Exit sleep |

### Step 3 — Read eFuse Factory Calibration

Three factory-calibrated trim values are stored in the chip's eFuse (OTP). They must be read on Page 1 and applied before writing any RF registers. If the validity check fails, initialization must abort.

```c
WriteReg(0x00, 0x01);    // PAGE_CFG: select Page 1
WriteReg(0x05, 0x00);    // OTP Mode Control: open eFuse access
WriteReg(0x04, 0x04);    // OTP Data: read row 0 (command)
Value_2 = ReadReg(0x04); // result: CHIP_VALID | calBit | FSYNVCO_TXCTK
WriteReg(0x04, 0x08);    // OTP Data: read row 1 (command)
Value_4 = ReadReg(0x04); // result: XTAL_TRIM in bits[7:4]
WriteReg(0x05, 0x01);    // OTP Mode Control: close eFuse access

if ((Value_2 & 0x0F) != 1) return FAIL;  // CHIP_VALID must equal 1

// Apply eFuse values while still on Page 1
WriteReg(0x47, 0x83 | ((Value_2 >> 1) & 0x70)); // FSYNVCO_TXCTK[2:0] → P1[0x47] bits[6:4]
WriteReg(0x43, 0x10 | ((Value_2 & 0x10) ? 0 : 1)); // calBit (inv of bit4) → P1[0x43] bit0
```

eFuse field summary:

| Field | Source | Target register | Role |
|-------|--------|-----------------|------|
| `CHIP_VALID` | `Value_2 & 0x0F` | validation only | must equal 1; abort if not |
| `calBit` | `!(Value_2 & 0x10)` | P1[0x43] bit[0] | PA current source trim |
| `FSYNVCO_TXCTK[2:0]` | `Value_2 bits[7:5]` | P1[0x47] bits[6:4] | VCO TX clock trim |
| `XTAL_TRIM[3:0]` | `Value_4 bits[7:4]` | P0[0x05] bits[3:0] | crystal load-cap trim (written in Step 5) |

### Step 4 — Page 1 Pre-Configuration

Still on Page 1. Write fixed RF analog tuning constants. The values are mode-dependent; only LongRange adds one extra write at the top.

**XN297L Normal and XN297L Enhanced (32 MHz):**
```c
WriteReg(0x27, 0xAA);
WriteReg(0x32, 0x1E);   // Gaussian filter: INBAND_DELAY, GAUSS_SCALE
WriteReg(0x33, 0x19);   // Gaussian filter: OUTBAND_DELAY, DF_SEL
WriteReg(0x37, 0x15);   // RX LNA tuning
WriteReg(0x3A, 0x14);   // RX filter tuning
WriteReg(0x3E, 0xF1);   // FSYN PFD loop filter
WriteReg(0x41, 0xA2);   // VCO/PA control (0xA6 on 16 MHz)
WriteReg(0x46, 0xB0);   // PA bias — 9 dBm
WriteReg(0x4C, 0x48);   // TX DAC enable, LDO trim
```

**BLE Beacon (32 MHz):** same as above but **omit** P1[0x32] and P1[0x33] (Gaussian filter; not used in BLE mode).

**BLE LongRange (32 MHz):** same as BLE Beacon but **prepend** one additional write:
```c
WriteReg(0x0B, 0x30);   // enable BLE Coded PHY (LongRange) demodulator path
```

### Step 5 — Page 0 Configuration

Switch back to Page 0 and write all mode-specific protocol registers.

```c
WriteReg(0x00, 0x00);   // PAGE_CFG: back to Page 0
```

See [§6](#6-mode-specific-register-tables-32-mhz) for complete per-mode register tables.

Key constraint: `RF_CHANNEL_CFG` (P0[0x39]) **must** be written to `0x55` here. This sets the calibration frequency (2485 MHz, outside the ISM band). Do not change it until calibration (Step 6) completes.

### Step 6 — RF Calibration

Five-phase RF calibration sequence. Each phase must finish before starting the next.

```c
WriteReg(0x00, 0x01);               // PAGE_CFG: Page 1

// Phase 1 — VCO calibration
WriteReg(0x1B, 0x08);               // CAL_CTL: FSM_VCO_CAL
while ((ReadReg(0x70) & 0x40) == 0); // poll P1[0x70] bit6 — or delay ≥1 ms

// Phase 2 — Thermal / 2-point calibration
WriteReg(0x1B, 0x10);               // CAL_CTL: FSM_2P_CAL
DelayMs(55);                        // MANDATORY — do not reduce

// Phase 3 — Frequency offset calibration (requires RX mode)
WriteReg(0x02, 0x76);               // STATE_CFG: enter RX (shared register — accessible from Page 1)
DelayUs(200);                       // ≥200 µs for RFPLL to lock
WriteReg(0x1B, 0x20);               // CAL_CTL: FSM_OFST_CAL
while ((ReadReg(0x7F) & 0x80) == 0); // poll P1[0x7F] bit7 — or delay ≥2 ms

// Phase 4 — BW / filter calibration
WriteReg(0x1B, 0x40);               // CAL_CTL: FSM_BW_CAL
while ((ReadReg(0x6D) & 0x80) == 0); // poll P1[0x6D] bit7 — or delay ≥1 ms

// Phase 5 — DC offset calibration
WriteReg(0x1B, 0x80);               // CAL_CTL: FSM_DCOC
while ((ReadReg(0x7F) & 0x80) == 0); // poll P1[0x7F] bit7 — or delay ≥2 ms

// Finish
WriteReg(0x1B, 0x00);               // CAL_CTL: stop
WriteReg(0x02, 0x74);               // STATE_CFG: return to STB3
WriteReg(0x00, 0x00);               // PAGE_CFG: Page 0
WriteReg(0x73, 0xFF);               // RFIRQFLG: clear all IRQ flags

// Set operating channel (replaces calibration channel)
WriteReg(0x39, channel);            // e.g. 0x4E for 2478 MHz, 0x02 for BLE ch37
```

Notes:
- Poll loops may spin indefinitely if RF registers are misconfigured. Use timeout fallbacks during bring-up.
- Phase 2 has no status register — the 55 ms delay is mandatory and cannot be shortened.
- Phase 3 requires the chip to be in RX mode. `STATE_CFG` is a shared register and responds at address 0x02 regardless of current page.
- After this step the chip is in STB3 with the operating channel set. Initialization is complete.

## 5. Register Explanations

This section explains **why** each register is written to its specific value and what it controls. Registers are grouped by function.

---

### 5.1 Page & State Registers

#### P0[0x00] PAGE_CFG

Selects the active register bank. Always write 0x01 before accessing Page 1 registers, and restore to 0x00 before TX/RX. Since `STATE_CFG` (0x02) is shared, it can be used to enter RX mode (0x76) during Phase 3 calibration without first switching back to Page 0.

#### P0[0x02] STATE_CFG

Main power state machine. Bit 6 (`EN_LS_3V`) enables the high-voltage 3V supply required by all RF analog blocks — this is why the init sequence writes 0x04 first (3V off, OPERATE_MODE=4) and then 0x74 (3V on, OPERATE_MODE=4). Writing 0x75 or 0x76 directly from power-on without this two-stage entry would leave the RF analog unpowered.

`OPERATE_MODE` field [2:0]:

| Value | State | Description |
|-------|-------|-------------|
| 0 | Deep Sleep | All clocks off; register contents lost |
| 1 | Sleep | Crystal stopped; registers retained |
| 4 | STB3 | Crystal running; registers accessible; normal idle state |
| 5 | TX | Transmitting |
| 6 | RX | Receiving |

#### P0[0x03] SYS_CFG

`SOFT_RSTL` (bit1, active-low): writing 0x00 asserts the reset, 0x02 releases it. This resets all Page 0 user registers to their power-on defaults, giving a known starting point before mode-specific values are written. Called in Step 2 before any protocol register writes.

---

### 5.2 Interface & Crystal Trim

#### P0[0x05] XTAL_CFG (also named IPTAT_CFG in ES-Tool source)

Crystal load-capacitor trim loaded from eFuse:
```
WriteReg(0x05, (Value_4 >> 4) | 0xC0)
```
`Value_4` bits[7:4] hold the factory-calibrated trim that compensates for PCB parasitic capacitance and crystal manufacturing variation. The 0xC0 constant sets two required enable bits. An incorrect trim shifts the crystal frequency by ±tens of ppm, which is enough to fail BLE reception (BLE specification requires better than ±50 ppm).

#### P0[0x06] LP_CFG (named I2C_CFG in the RM)

| Bits | Field | Default | Description |
|------|-------|---------|-------------|
| [3] | IRQ_I2C_MUX_EN | 0 | Route interrupt signal onto SDA pin when bus is idle |
| [2:0] | — | 101 | Reserved — must remain 0b101 |

Write 0x0D (IRQ_I2C_MUX_EN=1) during normal operation: the IRQ pin is not brought out separately on I2C hardware — it is multiplexed onto SDA. Without this, the firmware has no interrupt signal.

Write 0x05 (IRQ_I2C_MUX_EN=0) before entering sleep: disables IRQ routing to prevent spurious wake-ups from bus noise when the MCU drives SDA low during unrelated I2C transactions.

---

### 5.3 Protocol Configuration

#### P0[0x07] WMODE_CFG0

The primary mode selector. Bit-field breakdown for each mode:

| Bits | Field | XN297L Normal | XN297L Enhanced | BLE |
|------|-------|:---:|:---:|:---:|
| [7:6] | CRC_MODE | `10` (2 B) | `10` (2 B) | `11` (3 B, CRC-24) |
| [5:4] | WORK_MODE | `00` (XN297L) | `00` (XN297L) | `11` (BLE) |
| [3] | WHITEN_EN | 1 | 1 | 1 |
| [2] | CRC_SKIP_ADDR | 0 | 0 | 1 |
| [1] | TX_NOACK | 0 | 0 | 1 |
| [0] | ENDIAN | 1 (MSB-first) | 1 | 0 (LSB-first) |
| **Value** | | **0x89** | **0x89** | **0xFC** |

`WORK_MODE=11`: switches the chip to the BLE demodulator path, BLE access address correlator, BLE CRC-24 polynomial, and LSB-first bit ordering. `WORK_MODE=00` uses the XN297L-compatible path with Nordic-style addressing.

`CRC_SKIP_ADDR=1` in BLE: the BLE access address is part of the RF framing but is **not** covered by the BLE CRC-24 — the CRC covers only the PDU. This bit tells the CRC engine to start from the PDU, not from the access address.

`TX_NOACK=1` in BLE: BLE advertising has no acknowledgment mechanism. The chip must not wait for an ACK after transmitting a beacon.

`ENDIAN=0` in BLE: BLE transmits all fields LSB-first. XN297L uses MSB-first (Nordic-compatible).

`WORK_MODE=01` and `10` are not defined and must never be written.

#### P0[0x08] WMODE_CFG1

Secondary mode control:

| Bits | Field | XN297L Normal | XN297L Enhanced | BLE |
|------|-------|:---:|:---:|:---:|
| [7] | RX_GOON | 1 | 1 | 1 |
| [6] | PRI_EXIT_RX | 0 | 0 | 0 |
| [5] | FIFO_128_EN | 1 | 0 | 1 |
| [4] | DPY_EN | 0 | 1 | 1 |
| [3] | ENHANCE | 0 | 1 | 0 |
| [2] | — | 0 | 0 | 0 |
| [1:0] | ADDR_BYTE_LEN | `11` (5 B) | `11` (5 B) | `10` (4 B) |
| **Value** | | **0xA3** | **0x9B** | **0xB2** |

`RX_GOON=1` (all modes): chip stays in RX after each received packet. Without this, it returns to STB3 after every packet, requiring firmware to re-assert RX mode.

`DPY_EN=1` in enhanced and BLE modes: enables dynamic payload length extraction. In BLE mode, every advertising PDU carries its length in PDU header byte 1; the chip extracts and reports this length automatically. In XN297L Normal, the payload length is fixed and set by `RXPLLEN_CFG`.

`ENHANCE=1` only in XN297L Enhanced: enables auto-ACK, PID duplicate detection, and max-retransmit counter. **Not used for BLE** — BLE advertising has no ACK mechanism.

`ADDR_BYTE_LEN=10` (4 B) in BLE: the BLE access address is exactly 32 bits. The 5th address register byte is unused.

`FIFO_128_EN=0` for XN297L Enhanced: the enhanced protocol uses 64-byte FIFO. All other modes use 128-byte FIFO.

#### P0[0x0B] RFIRQ_CFG

Interrupt mask register — 0 = interrupt **enabled** (asserts IRQ/SDA pin), 1 = **masked**.

| Bit | Name | 0x7F | 0x28 |
|-----|------|:---:|:---:|
| 7 | TX_IRQ_MSK | 0 (TX enabled) | 0 (TX enabled) |
| 6 | TX_MAX_RT_IRQ_MSK | 1 (masked) | 0 (enabled) |
| 5 | RX_ADDR_ERR_MSK | 1 | 1 |
| 4 | RX_CRC_ERR_IRQ_MSK | 1 | 0 (enabled) |
| 3 | RX_LEN_ERR_IRQ_MSK | 1 | 1 |
| 2 | RX_PID_ERR_IRQ_MSK | 1 | 0 (enabled) |
| 1 | RX_TIMEOUT_IRQ_MSK | 1 | 0 (enabled) |
| 0 | RX_IRQ_MSK | 1 | 0 (enabled) |
| **Mode** | | XN297L Normal, BLE | XN297L Enhanced |

`0x7F`: unmasks only TX_IRQ — suitable for a TX-only scenario where the firmware polls for TX completion.

`0x28`: unmasks TX_IRQ, TX_MAX_RT_IRQ (retransmit failure), RX_CRC_ERR, RX_PID_ERR (duplicate detection), RX_TIMEOUT_IRQ, and RX_IRQ — all events relevant to the enhanced bidirectional protocol.

### 5.4 Packet Structure

#### P0[0x19] PKT_EXT_CFG

Controls automatic header insertion and FEC encoding:

| Bits | Field | XN297L | BLE Beacon | BLE LongRange |
|------|-------|:---:|:---:|:---:|
| [6] | HDR_LEN_EXIST | 0 | 1 | 1 |
| [5:4] | HDR_LEN_NUMB | — | `10` (2 B) | `01` (1 B) |
| [3] | PRI_TX_FEC | 0 | 0 | 1 |
| [2] | PRI_RX_FEC | 0 | 0 | 1 |
| [1:0] | PRI_CI_MODE | 00 | 00 | 00 |
| **Value** | | **0x00** | **0x60** | **0x5C** |

`HDR_LEN_EXIST=1`: the chip auto-prepends header bytes from `TXHDR0/1_CFG` to every TX packet. The TX FIFO must contain only the raw payload — **no header bytes written by firmware**.

`HDR_LEN_NUMB=10` (2 bytes) in BLE Beacon: byte 0 = `TXHDR0_CFG` (PDU type), byte 1 = auto-calculated PDU length. Together they form the 2-byte BLE advertising PDU header.

`HDR_LEN_NUMB=01` (1 byte) in LongRange: BLE Coded PHY uses FEC over the entire PDU body. The auto-inserted header is reduced to 1 byte; the FEC framing handles the rest of the packet structure.

`PRI_TX_FEC=1 / PRI_RX_FEC=1` in LongRange: enables the forward error correction encoder (TX) and decoder (RX) for BLE Coded PHY. FEC extends range at the cost of higher on-air time.

#### P0[0x1A] WHITEN_CFG / SCR_CFG

Whitening LFSR seed and address-skip control:

| Bits | Field | XN297L | BLE |
|------|-------|:---:|:---:|
| [7] | ACCADDR_SCR_DIS | 0 | **1** |
| [6:0] | WHITEN_SEED | 0x7F | channel-dependent |

`ACCADDR_SCR_DIS=1` (bit 7) is **mandatory for all BLE modes**. The BLE access address and preamble are never whitened in BLE — only the PDU is. Setting bit 7 tells the LFSR engine to skip the address field. The register value is always `0x80 | seed`, not just the seed alone.

BLE whitening seed formula:
```
WHITEN_CFG = 0x80 | bit_reverse_7bit(channel_index | 0x40)
```
where `bit_reverse_7bit(x)` reverses the 7 LSBs of `x`, and `channel_index` is the BLE logical channel number.

Pre-computed values for advertising channels:

| BLE ch | Frequency | RF_CH | channel_index | WHITEN_CFG |
|--------|-----------|-------|:---:|:---:|
| 37 | 2402 MHz | 0x02 | 37 | **0xD3** |
| 38 | 2426 MHz | 0x1A | 38 | **0xB3** |
| 39 | 2480 MHz | 0x50 | 39 | **0xF3** |

Derivation for ch37: `37 | 0x40 = 0b1100101`, bit-reverse 7 bits → `0b1010011 = 0x53`, register = `0x80 | 0x53 = 0xD3`.

When changing BLE channel, update both `RF_CHANNEL_CFG` (P0[0x39]) and `WHITEN_CFG` (P0[0x1A]).

#### P0[0x1B] TXHDR0_CFG

Auto-inserted TX header byte 0. Value in BLE Beacon mode: **0x42**.

```
0x42 = 0b01000010
  bit[6]   = TxAdd = 1  (advertiser uses a random address)
  bits[3:0] = 0x02      (PDU type: ADV_NONCONN_IND)
```

Not written in LongRange mode (stays at default 0x00): LongRange inserts only 1 header byte and its content is determined by the Coded PHY framing, not by `TXHDR0_CFG`.

### 5.5 TX Timing & Mode

#### P0[0x29] TXAUTO_CFG

Auto-retransmit delay and count. Only meaningful in enhanced mode (`ENHANCE=1`).

| Bits | Field | Default | Enhanced SDK |
|------|-------|---------|:---:|
| [7:4] | ARD | 0000 | 0000 (250 µs) |
| [3:0] | ARC | 0011 | 0011 (3 retransmits) |

XN297L Normal and BLE: explicitly write **0x00** (ARD=0, ARC=0 = no retransmit). Required because the power-on default is 0x03 (3 retransmits), which would cause unintended retry behaviour.

XN297L Enhanced: leave at power-on default 0x03 (250 µs delay, 3 retransmits). The SDK does not write this register in the enhanced example.

#### P0[0x2A] TRXMODE_CFG

TX and RX operating mode:

| Bits | Field | XN297L Normal | BLE Beacon | BLE LongRange |
|------|-------|:---:|:---:|:---:|
| [7] | REG_TX_CFG_MODE | 0 (single) | 0 (single) | 0 (single) |
| [6:5] | REG_RX_CFG_MODE | 10 (continuous) | 10 (continuous) | 10 (continuous) |
| [0] | W_PRE_SYNC_EN | 1 | 1 | **0** |
| **Value** | | **0x41** | **0x41** | **0x40** |

`W_PRE_SYNC_EN=0` in LongRange: standard BLE uses a 1-byte 0x55/0xAA preamble that the pre-sync detector looks for. BLE Coded PHY (LongRange) uses a different preamble structure handled by the `DEMOD_BLE_LONG_RANGE` demodulator path (P1[0x0B]=0x30). Leaving the standard pre-sync enabled would cause false triggers and prevent correct LongRange reception — hence bit0=0.

---

### 5.6 BLE Filters

#### P0[0x2D] BLEMATCH_CFG0

BLE RX packet filter. Written **0x04** in BLE init.

```
0x04 = 0b00000100
  bits[6:4] = WL_MATCH_MODE   = 000 (whitelist disabled — accept any source address)
  bits[3:2] = BLELEN_MATCH_MODE = 01 (equal length filter)
```

The equal length filter rejects received BLE PDUs whose length field does not match `RXPLLEN_CFG`. This prevents short noise bursts and packets from other BLE PDU types from filling the FIFO. The whitelist filter (WL_MATCH_MODE) is disabled by default — enable it to restrict reception to a specific advertiser address.

#### P0[0x2E] BLEMATCH_CFG1

Pattern match threshold. Default = **0x28** = 40. Sets the correlation threshold for BLE access address detection. The chip counts bit matches between the received access address and `0x8E89BED6`; a packet is accepted only when the match count meets this threshold. Value 40 of 32 bits is PANCHIP's empirical setting balancing false-accept and false-reject rates. Do not modify without PANCHIP guidance.

---

### 5.7 RF Channel & AGC

#### P0[0x39] RF_CHANNEL_CFG

Center frequency = 2400 + RF_CH [MHz].

Written **0x55** (= 85 → 2485 MHz) during Steps 5 and the start of Step 6. This frequency lies **outside** the 2.4 GHz ISM band (2400–2483 MHz), which prevents the calibration run from interfering with nearby devices and ensures the VCO is calibrated against a clean, uncontested frequency. After calibration completes, the operating channel is written in its place.

BLE advertising channels:

| BLE ch | RF_CH | Frequency |
|--------|-------|-----------|
| 37 | 0x02 | 2402 MHz |
| 38 | 0x1A | 2426 MHz |
| 39 | 0x50 | 2480 MHz |

#### P0[0x43] RF_PA_MODE_CFG

PA and RX analog mode selection. Value **0x3A** (32 MHz):

```
0x3A = 0b00111010
  bits[5:4] = TXPA_MODE_SEL = 11  (high-performance PA for 1 Mbps / 2 Mbps / BLE)
  bit[3]    = EN_RXADCCLK   = 1   (enable RX ADC clock)
  bits[1:0] = RXFLTR_IF     = 10  (1 Mbps / 2 Mbps IF filter bandwidth)
```

`TXPA_MODE_SEL=11` is required for 1 Mbps and BLE data rates. Mode 00 targets 250 kbps/FS01/FS32. Using the wrong mode degrades PA efficiency or RF output matching.

On 16 MHz crystal: value is **0x32** (`TXPA_MODE_SEL=01`), reflecting the different reference frequency for the PA tuning path.

#### P0[0x44] RF_PA_POUT_CFG

TX output power select:

| Value | TXPA_POUT_CRNT [7:4] | TXPA_LDO_SEL [3:0] | TX power |
|-------|:---:|:---:|:---:|
| 0x8C | 1000 | 1100 | **9 dBm** |
| 0x84 | 1000 | 0100 | **0 dBm** |

Both settings use the same PA current (`TXPA_POUT_CRNT=1000`); the LDO supply voltage is what changes the output power.

#### P0[0x55–0x57] RSSI AGC Threshold Registers

```
P0[0x55] RF_RSSI_TH1 = 0xDD
P0[0x56] RF_RSSI_TH2 = 0xC9
P0[0x57] RF_RSSI_TH3 = 0xB7
```

Three RSSI breakpoints at which the automatic gain control switches gain stages. Values are empirically tuned by PANCHIP for the target sensitivity and selectivity specifications of the chip. Copy verbatim from ES-Tool output; do not derive from any formula.

#### P0[0x5A–0x5D] RSSI Fixed Calibration Words

```
P0[0x5A] RF_RSSI_FIX0 = 0x10
P0[0x5B] RF_RSSI_FIX1 = 0xFD
P0[0x5C] RF_RSSI_FIX2 = 0xE9
P0[0x5D] RF_RSSI_FIX3 = 0xDC (XN297L) | 0xD4 (BLE)
```

Fixed-gain RSSI offset coefficients. `FIX3` differs between XN297L (0xDC) and BLE (0xD4) because BLE mode uses a higher gain configuration in the final AGC stage to achieve BLE sensitivity targets. The different `FIX3` value recalibrates the RSSI reading to account for this extra gain.

#### P0[0x5E–0x61] AGC Gain Table Entries

```
P0[0x5E] RF_GAIN_WORD0 = 0x02  (all modes)
P0[0x5F] RF_GAIN_WORD1 = 0x06  (all modes)
P0[0x60] RF_GAIN_WORD2 = 0x0E  (all modes)
P0[0x61] RF_GAIN_WORD3 = 0x2E (XN297L) | 0x3E (BLE)
```

Gain step values for the AGC state machine. `GAIN_WORD3` (the highest gain step) is 0x3E in BLE mode — larger than the XN297L value 0x2E — because BLE requires higher front-end gain to meet the BLE sensitivity specification.

### 5.8 RF Timing

#### P0[0x66] RF_TX_ANA_TIME

TX analog chain warm-up time before data transmission begins. PA and RF filters need time to settle after being powered on.

| Crystal | Value |
|---------|:---:|
| 32 MHz | 0x34 |
| 16 MHz | 0x64 |

The 16 MHz value is roughly double (reference period is twice as long), so more reference clock cycles are needed for equivalent physical time.

#### P0[0x68] RF_RX_PLL_SETUP

RX RF PLL lock time. After entering RX state, the synthesizer needs this long to lock to the receive frequency before reliable demodulation can begin.

| Crystal | Value |
|---------|:---:|
| 32 MHz | 0x0D |
| 16 MHz | 0x19 |

#### P0[0x6E] RF_PA_RAMP_DLY

PA output ramp timing for spectral emission mask compliance.

```
0x20 = 0b00100000
  bits[6:4] = PA_RAM_DN_DLY_SEL = 010
  bits[2:0] = PA_RAM_UP_DLY_SEL = 000
```

A controlled PA ramp reduces spectral splatter during TX burst edges. Value differs between crystal frequencies (0x40 on 16 MHz).

#### P0[0x6F] MISC_CFG

Written **0x10** in BLE modes only:

```
0x10 = PID_LOW_SEL = 1
```

In BLE, the packet identifier (PID — used to detect duplicate advertising packets during scanning) is encoded in a different bit position than in XN297L format. `PID_LOW_SEL=1` directs the chip to extract PID bits from the correct LSB position for BLE PDU format. Without this, BLE RX produces false duplicate-packet detections. Not needed in XN297L modes.

### 5.9 Page 1 — RF Analog Tuning

#### P1[0x0B] = 0x30 (LongRange only)

```
0x30 = 0b00110000
  bit[5] = DEMOD_BLE_LONG_RANGE       = 1
  bit[4] = DEMOD_EN_OFF_EST_TIMEOUT   = 1
```

`DEMOD_BLE_LONG_RANGE=1`: switches the receive baseband to the BLE Coded PHY demodulator path, which includes FEC decoding and the extended timing recovery needed for S2/S8 coding. Without this bit, the standard 1 Mbps demodulator is used and LongRange packets cannot be decoded.

`DEMOD_EN_OFF_EST_TIMEOUT`: enables the offset estimation timeout in the LongRange demodulator, required for correct BLE Coded PHY synchronization.

Not written for standard BLE Beacon — the standard 1 Mbps demodulator remains active.

#### P1[0x27] = 0xAA

RF analog bias unlock/control constant. Written both at initialization and during TX power level changes, always with the same value. Acts as a prerequisite write that enables subsequent analog register updates within the same Page 1 session.

#### P1[0x32] = 0x1E and P1[0x33] = 0x19 (XN297L only)

Gaussian GFSK modulation filter parameters for the TX baseband:

```
P1[0x32] = 0x1E = 0b00011110
  bits[7:4] = INBAND_DELAY  = 0001 (in-band filter delay)
  bits[2:0] = GAUSS_SCALE   = 110  (filter amplitude scaling)

P1[0x33] = 0x19 = 0b00011001
  bits[7:4] = OUTBAND_DELAY = 0001 (out-of-band filter delay)
  bits[2:0] = DF_SEL        = 001  (frequency deviation select)
```

XN297L uses GFSK modulation with BT ≈ 0.5. These registers tune the digital Gaussian pre-modulation filter in the TX baseband to shape the modulation spectrum according to the XN297L spec.

BLE also uses GFSK (BT=0.5) but routes through a **separate dedicated BLE modulator path**. P1[0x32] and P1[0x33] have no effect on BLE transmission and are intentionally omitted from BLE init sequences.

#### P1[0x37] = 0x15 and P1[0x3A] = 0x14

RX LNA (low-noise amplifier) bias and channel filter tuning constants. Fixed values valid for both XN297L and BLE at 2.4 GHz. Empirically determined by PANCHIP. Do not modify.

#### P1[0x3E] = 0xF1

FSYN (frequency synthesizer) PFD (phase-frequency detector) loop filter setting. Controls PLL loop bandwidth for stable VCO operation. Common to all modes.

#### P1[0x41] = 0xA2 (32 MHz) / 0xA6 (16 MHz)

VCO and PA initialization control. The different value between crystal frequencies reflects different VCO divide ratios and tuning ranges for the two reference frequencies.

#### P1[0x43] = 0x10 | calBit (eFuse-derived)

PA current source trim:
```
calBit = (OTP_value2 & 0x10) ? 0 : 1
P1[0x43] = 0x10 | calBit       → 0x10 or 0x11
```

Bit 4 (`EN_TX_DAC`=1) is always set. Bit 0 is a factory single-bit trim that compensates for process variation in the PA current source, ensuring consistent TX output power (±1 dB) across chips from different wafer batches.

#### P1[0x46] = 0xB0 (9 dBm) / 0xBD (0 dBm)

PA quiescent bias current. Higher bias delivers more RF output power. Changed by the TX power control sequence alongside P1[0x3C] and P0[0x44].

#### P1[0x47] = 0x83 | ((OTP_value2 >> 1) & 0x70) (eFuse-derived)

VCO TX clock divider trim:
```
P1[0x47] = 0x83 | ((OTP_value2 >> 1) & 0x70)
```

`EN_IPOLY` (bit 7) = 1 always. Bits[6:4] = `FSYNVCO_TXCTK[2:0]` from OTP word 2 bits[7:5]: factory-calibrated VCO frequency divider ratio for TX mode. Compensates for VCO center frequency spread across chips, ensuring the TX carrier lands accurately on the target channel.

#### P1[0x4C] = 0x48

TX DAC enable and LDO trim:
```
0x48 = 0b01001000
```
Enables the TX signal path DAC and sets the high-power LDO supply trim for the TX analog chain.

### 5.10 Page 1 — Calibration Control

#### P1[0x1B] CAL_CTL

Shares the address 0x1B with Page 0 `TXHDR0_CFG` — completely different physical register. One-hot write triggers each calibration phase; poll the corresponding status register before proceeding.

| Write | Phase name | Status reg | Done bit | Min delay |
|-------|------------|------------|:---:|-----------|
| 0x08 | FSM_VCO_CAL | P1[0x70] | bit[6] | poll only |
| 0x10 | FSM_2P_CAL (thermal) | — | — | **55 ms mandatory** |
| 0x20 | FSM_OFST_CAL (freq offset) | P1[0x7F] | bit[7] | poll, ~2 ms |
| 0x40 | FSM_BW_CAL (filter BW) | P1[0x6D] | bit[7] | poll, ~1 ms |
| 0x80 | FSM_DCOC (DC offset) | P1[0x7F] | bit[7] | poll, ~2 ms |

What each phase does and why it is required:

- **FSM_VCO_CAL**: coarse-tunes the VCO center frequency against the crystal reference. Without this the VCO may not cover the target channel.
- **FSM_2P_CAL**: two-point temperature calibration for RF drift compensation. The mandatory 55 ms allows the crystal oscillator and thermal sensor to reach thermal equilibrium — shortening this window corrupts the temperature coefficients and causes RF frequency drift with temperature changes.
- **FSM_OFST_CAL**: fine frequency offset correction using the receive IQ mixer. **Requires chip to be in RX mode** (STATE_CFG=0x76) because it correlates received IQ signal tones. Skipping RX mode entry before this phase causes the calibration state machine to hang.
- **FSM_BW_CAL**: calibrates the IF (channel) filter pole frequency to correct for process variation in the filter capacitors.
- **FSM_DCOC**: nulls I/Q mixer DC offsets. Uncompensated DC offsets cause a carrier leak at the TX center frequency (local oscillator leakage), degrading spectral purity.

Phases must run in this exact order. Skipping or reordering them causes TX/RX failure.

### 5.11 eFuse Access

#### P1[0x05] — OTP Mode Control

| Write | Effect |
|-------|--------|
| 0x00 | Open eFuse for readout |
| 0x01 | Close eFuse access |

Must bracket all OTP register reads.

#### P1[0x04] — OTP Data Register

Write a row command, then read the result from the same address:

| Write | Read result | Fields |
|-------|-------------|--------|
| 0x04 | OTP word 2 | `CHIP_VALID`[3:0], `calBit`[4], `FSYNVCO_TXCTK`[7:5] |
| 0x08 | OTP word 4 | `XTAL_TRIM`[7:4] |

## 8. BLE Mode Details

### Advertising Access Address

BLE advertising channels use the fixed 32-bit access address **0x8E89BED6**, stored LSB-first across four 1-byte registers:

```
P0[0x0F] = 0xD6   // byte 0 — LSB, first on air
P0[0x10] = 0xBE   // byte 1
P0[0x11] = 0x89   // byte 2
P0[0x12] = 0x8E   // byte 3 — MSB
```

The same address is written to the TX address registers (P0[0x14..0x17]). The 5th byte (P0[0x13] / P0[0x18]) stays at its default 0xCC — it is unused because address width is set to 4 bytes.

Note: LongRange mode does **not** write the access address registers. The LongRange access address is handled differently (default 0xCC×4 value is used as a placeholder; the actual LR sync word is managed by the Coded PHY demodulator).

### Whitening Seed Formula

```c
uint8_t ble_whiten_cfg(uint8_t channel_index) {
    uint8_t x = channel_index | 0x40;
    uint8_t r = 0;
    for (int i = 0; i < 7; i++) {
        r = (r << 1) | (x & 1);
        x >>= 1;
    }
    return 0x80 | r;   // bit7=ACCADDR_SCR_DIS must always be set
}
```

To update the BLE channel at runtime: write both `P0[0x39]` (RF frequency) and `P0[0x1A]` (whitening seed).

### PDU Auto-Insertion and TX FIFO Format

When `PKT_EXT_CFG[HDR_LEN_EXIST]=1` (BLE Beacon and LongRange init), the chip automatically prepends the PDU header. The TX FIFO must contain **only** the raw payload:

```
TX FIFO for ADV_NONCONN_IND: [AdvA: 6 bytes, LSB-first] [AdvData: 0–31 bytes]
```

The chip prepends the 2-byte PDU header automatically:
- Byte 0: `TXHDR0_CFG` = 0x42 = `ADV_NONCONN_IND | TxAdd=1`
- Byte 1: auto-calculated PDU length = TxLen (AdvA + AdvData)

`TXPLLEN_CFG` (P0[0x0A]) must be set to the number of bytes in the FIFO (AdvA + AdvData only — not counting the auto-inserted header).

### White List (RX Address Filter)

```
P0[0x2F] = WhiteList[0]   // byte 0 (LSB) — default 0x00
P0[0x30] = WhiteList[1]
P0[0x31] = WhiteList[2]
P0[0x32] = WhiteList[3]
P0[0x33] = WhiteList[4]
P0[0x34] = WhiteList[5]   // byte 5 (MSB)
P0[0x35][5:0] = WhiteListOffset   // byte offset within received payload for comparison
P0[0x2D][6:4] = WL_MATCH_MODE    // 000=disabled, 001–110=compare 1–6 bytes
```

## 9. Post-Initialization Operations

### TX

```c
void TxStart(void)
{
    WriteReg(0x02, 0x74);   // ensure STB3
    WriteReg(0x73, 0xFF);   // clear all IRQ flags
    WriteReg(0x02, 0x75);   // enter TX
}
```

Write payload to FIFO before calling `TxStart()`:
```c
WriteRegs(0x01, payload, length);   // burst-write to TRX_FIFO
```

TX completion: `RFIRQFLG` (P0[0x73]) bit 0 set (`TX_IRQ`). After TX:
```c
void TxStop(void) { WriteReg(0x02, 0x74); }
```

### RX

```c
void RxStart(void)
{
    WriteReg(0x02, 0x74);   // ensure STB3
    WriteReg(0x73, 0xFF);   // clear all IRQ flags
    WriteReg(0x02, 0x76);   // enter RX
}
```

On `RX_IRQ` (P0[0x73] bit 7):
```c
uint8_t len     = ReadReg(0x77);           // received payload length
uint8_t pipenum = (ReadReg(0x74) >> 4) & 0x07;
ReadRegs(0x01, buf, len);                  // drain FIFO
WriteReg(0x73, 0xFF);                      // clear IRQ
```

```c
void SetChannel(uint8_t ch) {
    WriteReg(0x39, ch);   // ch = freq_MHz - 2400, valid 0–83
```

### Sleep / Wakeup

```c
void EnterSleep(void)
{
    WriteReg(0x02, 0x74);  // ensure STB3
    WriteReg(0x06, 0x05);  // LP_CFG: disable IRQ routing
    WriteReg(0x02, 0x21);  // enter sleep
}

void ExitSleep(void)
{
    WriteReg(0x02, 0x22);  // exit sleep
    WriteReg(0x02, 0x74);  // STB3
    WriteReg(0x06, 0x0D);  // LP_CFG: re-enable IRQ routing
    DelayMs(1);             // crystal stabilization
}
```

Sleep preserves all register values. No re-initialization is needed after wakeup.

### Carrier Wave Test

```c
void StartCarrierWave(void)     // XN297L Normal mode

    WriteReg(0x41, 0x20);
    WriteReg(0x42, 0x4E);
    WriteReg(0x00, 0x00);  // Page 0
```

## 10. 16 MHz vs 32 MHz Crystal

When using a 16 MHz crystal, the following registers in Step 5 have different values. Values derived from ES-Tool `RecommendRegPage0_Def` (col1=16 MHz, col2=32 MHz) and `RecommendRegPage1_Def`.

**Page 0 register differences:**

| Register | 16 MHz | 32 MHz | Notes |
|----------|:---:|:---:|-------|
| P0[0x43] | 0x32 | 0x3A | `TXPA_MODE_SEL` differs |
| P0[0x66] | 0x64 | 0x34 | TX analog setup time |
| P0[0x68] | 0x19 | 0x0D | RX RFPLL setup time |
| P0[0x6E] | 0x40 | 0x20 | PA ramp delay |

**Page 1 register differences:**

| Register | 16 MHz | 32 MHz | Notes |
|----------|:---:|:---:|-------|
| P1[0x3F] | 0xD2 | not written | 16 MHz only |
| P1[0x40] | 0x20 | not written | 16 MHz only |
| P1[0x41] | 0xA6 | 0xA2 | VCO/PA control |

**Additional Step 2 write required for 16 MHz (before entering Page 1):**
```c
WriteReg(0x37, 0xE0);   // crystal pre-configuration gate — 16 MHz hardware only
```

**IMPORTANT:** On 16 MHz crystal, the ES-Tool **omits** P0[0x5A]–P0[0x61] entirely from the init sequence. Those nine registers are only written on 32 MHz. Do not copy 32 MHz RF analog values into a 16 MHz init sequence.

## 11. Soft Reset

`SoftReset()` resets digital logic via `SOFT_RSTL`. Call from STB3 only. After soft reset, `PAN211_Init()` must be called again to re-run the full 6-step sequence.

```c
void SoftReset(void)
{
    WriteReg(0x03, 0x00);  // assert SOFT_RSTL
    DelayMs(1);
    WriteReg(0x03, 0x02);  // release SOFT_RSTL
    // must call Init() next
}
```

`SOFT_RSTL` resets all Page 0 user registers to defaults. It does **not** reset Page 1 RF analog registers or the eFuse-derived trim values — those remain from the previous initialization.

This is distinct from `POR_RSTL` (power-on reset of low-voltage domain), which is triggered by removing and re-applying power.

## 12. IRQ Flags

Status register: P0[0x73] `RFIRQFLG`. Write 1 to any bit to clear that flag. Write 0xFF to clear all.

| Bit | Flag | Event |
|-----|------|-------|
| 7 | `TX_IRQ` | TX complete — packet sent |
| 6 | `TX_MAX_RT_IRQ` | Max retransmits reached (Enhanced mode) — TX failed |
| 5 | `RX_ADDR_ERR_IRQ` | Address match error (FEC/spread-spectrum mode) |
| 4 | `RX_CRC_ERR_IRQ` | CRC check failed |
| 3 | `RX_LEN_ERR_IRQ` | Payload length error (Enhanced mode) |
| 2 | `RX_PID_ERR_IRQ` | Duplicate PID received (Enhanced mode) |
| 1 | `RX_TIMEOUT_IRQ` | RX timeout expired without packet |
| 0 | `RX_IRQ` | Valid packet received and in FIFO |

The `RFIRQ_CFG` register (P0[0x0B]) controls which flags assert the IRQ/SDA pin. A flag is always set in P0[0x73] regardless of the mask; the mask only controls the physical pin.

SDK flag constants (`pan211.h`):

| Constant | Value |
|----------|:---:|
| `RF_IT_TX_IRQ` | 0x80 |
| `RF_IT_MAX_RT_IRQ` | 0x40 |
| `RF_IT_ADDR_ERR_IRQ` | 0x20 |
| `RF_IT_CRC_ERR_IRQ` | 0x10 |
| `RF_IT_LEN_ERR_IRQ` | 0x08 |
| `RF_IT_PID_ERR_IRQ` | 0x04 |
| `RF_IT_RX_TIMEOUT_IRQ` | 0x02 |
| `RF_IT_RX_IRQ` | 0x01 |
| `RF_IT_ALL_IRQ` | 0xFF |
